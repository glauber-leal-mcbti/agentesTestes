## What good looks like
- Matlab files (.m), Simulink files (.slx or .md) that compile and executes.
- Give preference to work with .md files for Simulink.
- Structured file organization.
- Structured logic.
- Structed rules for requiriments write.
- Model inputs and outpus with data type information.
- Model inputs and outpus with physics mean information.
- Model inputs and outpus with limits specifications.

## What to avoid
- Unused codes chunks into .m files.
- Unused Simulink blocks.
- Models that dont compile or execute.
- Modify models without permission.
- Commit files to github without permission.
